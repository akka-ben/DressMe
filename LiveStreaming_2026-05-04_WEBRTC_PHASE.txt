Date modification: 2026-05-04

Objectif:
- Permettre un vrai test live entre deux appareils:
  - telephone: demarre le live
  - simulateur: voit le live en temps reel depuis le feed

Backend ajoute:

Backend modifie:

Logique backend:
- Creation d'une session live MongoDB via POST /api/v1/live/sessions
- Liste des lives actifs via GET /api/v1/live/sessions
- Fin de live via POST /api/v1/live/sessions/{live_id}/end
- WebSocket de signalisation via /api/v1/live/ws/{live_id}
- Relais WebRTC offer / answer / ice_candidate entre host et viewers
- Fin automatique de session si le host deconnecte
- Index MongoDB ajoutes pour live_sessions

Logique mobile:
- Ajout de react-native-webrtc
- Bouton LIVE du create flow ouvre LiveHostScreen
- LiveHostScreen capture camera + micro et cree une session live backend
- LiveHostScreen envoie le flux via WebRTC aux viewers connectes
- HomeFeedScreen recupere les lives actifs toutes les 5 secondes
- HomeFeedScreen affiche une section live cliquable au-dessus des stories
- LiveViewerScreen rejoint le live et affiche le flux remote en RTCView
- Chat live basique viewer -> host via WebSocket

Test reel attendu:

2. S'assurer que EXPO_PUBLIC_API_URL pointe vers http://IP_LOCAL:8000/api/v1 sur les deux appareils.
3. Lancer l'app sur le telephone et le simulateur.
4. Se connecter avec deux comptes differents.
5. Sur le telephone: creation -> LIVE -> bouton rouge.
6. Sur le simulateur: feed -> attendre la section live ou pull refresh -> cliquer sur le live.
7. Le flux camera du telephone doit apparaitre sur le simulateur.

Limite technique:
- WebRTC direct fonctionne bien en reseau local.
- Pour un usage production hors LAN/NAT difficile, il faudra ajouter un serveur TURN.
